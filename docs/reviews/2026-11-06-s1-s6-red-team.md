## 1. 決策深析

### D1：登入 CSRF 以「頁面新 token＋cookie 雙重提交」實現（零 JS 約束下）

- **本質：** 變更請求必須可歸因於「同源頁面產生的意圖」；零 JS 限制可供使用的通道為表單欄位與 cookie。
- **第一原理：** 沒有 JS 就沒有自訂 header；能自動附帶且跨站無法發送的載體只有 `SameSite=Strict` cookie。
- **最壞鏈（反演）：** (a) token 不輪替 → 登入 CSRF 重用；已由登入成功回應輪替 `ekpi_csrf` 為 session token 阻斷，且 `login_form_and_cookie_carry_the_same_csrf_token` 鎖定。(b) 若存在 XSS，任何 CSRF 控制皆失效——但零 JS＋無 `script-src` 使 XSS 面趨近於零。(c) 兩分頁同時開登入頁 → 後者覆寫 cookie，前者 POST 收到通用 403 重試一次。**量化成本：** 罕見 UX 路徑一次重試。
- **支持證據：** 5 條正/負測試（缺 token 403、不符 403、輪替 cookie 可變更、無 csrf cookie 403、actor 不可偽造）。
- **反駁證據：** 現代瀏覽器 `SameSite=Strict` 已阻擋跨站發送，雙重提交的邊際價值屬縱深防禦——**成本是測試面與兩分頁重試**，接受。
- **取捨：** 以「登入頁也發 pre-auth cookie」換取一致的中介層語義；替代案（登入完全豁免 CSRF，只靠同源守衛）被否決，因其使登入端點成為唯一無 token 的變更面。

### D2：核准工作流使用獨立 JSONL 帳鏈（而非擴充 governance ledger）

- **本質：** 不變式獨立的兩個 bounded context 應有獨立鏈；共用鏈會耦合爆炸半徑與重放驗證。
- **最壞鏈：** 兩條鏈需一起備份才描述同一時點——**演練卻只還原 repo**（本審查的關鍵發現，見 §3 IMP-021）。若操作者的 runtime JSONL 遺失，repo 可完美還原而歷史全滅，且現行 drill 無法發現。
- **支持證據：** 兩鏈各自 fail-closed（竄改/斷行/順序拒載，C1–C5）；C4 證明升級計數與階段持久化。
- **反駁證據：** 備份/驗證成本 ×2；若未來需要跨領域稽核視圖，需另建投影（尚未有需求）。
- **取捨：** 接受雙鏈成本；以相同工法（append+fsync+rename+lock+verify）與 UI 雙徽章降低維運認知負擔。

### D3：未接線端點一律誠實 501（而非回空資料）

- **本質：** API 回答是承諾；空陣列是對世界狀態的承諾，而伺服器尚未接線時無權做此承諾。
- **最壞鏈：** 消費者視 501 為永久而放棄整合 → 由契約文件明示 S4 範圍與已接線唯讀端點緩解。**量化：** 12 端點中 2 個已接線（真資料＋schema tag）、10 個維持 501 且各有理由欄。
- **支持證據：** 501 鎖定測試；契約測試斷言形狀、階段數、任務欄位、401/501 語義。
- **反駁證據：** 「看起來不完整」對展示不利——與不編造鐵律衝突時，誠實優先。
- **取捨：** 以「先契約後上線」換取可信度；寫入 API 直至冪等鍵/重放防護有 SDD 才實作。

### D4：決策匯出不含時間戳（決定性 vs 溯源）

- **本質：** H-6 重放紀律要求同輸入同輸出**逐位元組**；時間戳必破。
- **最壞鏈：** 舊匯出與新匯出無法區分 → 溯源曖昧。緩解：匯出位於修訂標記的 out 目錄，register/證據列綁修訂；**量化：** 兩次執行逐位元組比對鎖定（n=種子語料全量）。
- **反駁證據：** 消費者若需要 `generated_at`，未來可以**新增選填欄位**（向後相容）或側車檔；屆時需版本決策（`ekpi-decisions-v2` 可加選填欄，屬相容變更）。
- **取捨：** 現在不做側車檔（無消費者），列為契約文件的已知選項。

### D5：任務 ID 以「任務數」而非「事件數」編號（S2 期間由測試發現並修復）

- **本質：** 識別碼必須在無關 append 下穩定。
- **最壞鏈（修復前）：** 外部引用（筆記/工單）指向 `TSK-000001`，一筆定義事件即讓編號平移 → 靜默錯引。
- **證據：** C1 重開重放一致；修復前後測試紅綠可查（S2 commit 說明）。
- **取捨：** 無——此為純缺陷修復。
