# Domain docs

This is a single-context repository: GLOSSARY.md is the shared product vocabulary and docs/adr/ records engineering decisions.

## Read before exploring

- GLOSSARY.md for approved terms.
- The relevant records in docs/adr/ for engineering decisions.
- For governance product changes, use docs/governance/05-functional-spec-v1.md for behavior, docs/governance/06-data-and-state-model-v1.md for identities and transitions, and docs/governance/08-decision-register.md for accepted decisions and unresolved items.
- For architecture and stack choices, use docs/tech-selection-round1.md and README.md.

Use glossary terms in issues, specs, code, and tests. When a term is not defined or sources conflict, record the gap and use /domain-modeling to resolve it; do not silently invent business semantics or turn an unresolved business decision into a code rule.
