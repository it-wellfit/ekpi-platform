# 驗收、回歸與需求追溯矩陣 v1.0

**用途：** 將每項必要需求落到可重複執行的驗收案例。除原型回歸基線外，本矩陣是目標產品規格，並非聲稱所有案例已在目前原型通過。各案例結果初始為 `NOT RUN`；執行時須填入環境、建置版本、資料集、操作者、時間、證據與缺陷 ID。

## 1. 執行紀錄契約

每次執行記錄：測試 ID／需求 ID、環境與設定版本、程式版本／commit、測試資料識別碼、前置條件、執行者、開始／結束時間、每一步實際結果、截圖／日誌／API trace 證據連結、PASS／FAIL／BLOCKED、缺陷編號、修正版本及重測結果。只有全部預期結果達成且證據可查才可標 `PASS`。租戶、資料、權限或業務決策未備妥時標 `BLOCKED` 並列阻擋因素，不能標 PASS。

## 4. 上線／交付退出條件

- 每個已納入發版的 MUST 需求有驗收案例；阻擋性案例全部 PASS，未完成案例明確標 BLOCKED 並不得冒稱符合。
- 無未解決阻擋性缺陷；高嚴重度缺陷有經授權的風險接受、負責人與期限，且不得涉及不可豁免條件。
- 12 階段與 5 關卡可走查；文件版本變更、來源拒絕、重複證據、跨部門交接、退回、變更與 CAPA 皆完成端到端測試。
- 追溯矩陣每個 FR/NFR 都有結果及可檢視證據；試點指標由業務負責人核定並簽收。
- IT／資安／資料治理核准身分、分類、連接器、保留、備份與營運；流程擁有者和文件控制者核准流程／封存方法。
- 交付設定與整合清冊、需求／測試追溯、作業／管理手冊、教育訓練、維運責任、復原／回退方法、版本說明及已知限制。
