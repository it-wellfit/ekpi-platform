# 跨專案治理試點套件

本套件把治理藍圖拆成可追溯的業務探索、需求、功能互動、資料／狀態、安全整合、驗收與決策基線，供業務、品質、文件管理、UX、開發及 IT 共同審查。內容依使用者提供的「頂級專案品質檢查與文件管理優化方案」展開；尚未進行真實組織訪談、租戶盤點或基線量測。`MUST` 表示目標產品必須具備，不代表本機原型已實作或企業已核准。

## 規格成熟度與追溯規則

05–07 定義通用目標產品的可開發行為與資料契約；08 將不可由規格作者臆測的業務參數列為明確決策；09 定義需求品質、研究依據和驗證方法。每項正式需求須在 04 找到一個或多個驗收案例，案例執行前記為 `NOT RUN`。原型已具備、部分具備或尚未建置的能力，依 04 §5 的程式碼盤點區分。需求決策尚未完成時，相關試點可使用已標明的人工控制，但不可把它算作自動化或正式符合。

## 原型邊界

`cargo run --bin governance-web` 啟動本機治理原型。預設資料位於使用者本機 AppData，亦可透過 `EKP_GOVERNANCE_DATA` 指定位置。原型會保存手動登錄的專案、文件證據參照、流程草稿、品質事件和追加式稽核事件；不會複製雲端文件，也不會連線至 Microsoft、Google 或 AI 服務。它不提供企業身分驗證、租戶隔離、完整狀態機或法規認證，不應對外公開或存放機密／受管制資料。原型的實際差距見 04 §5。

試點應先以非敏感、已獲授權的流程資料驗證欄位、狀態及工作方式。完成真實租戶工具盤點、存取控制和資料分類審查後，才能設計正式連接器與多使用者部署。
