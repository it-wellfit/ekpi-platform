# 工具試點操作手冊

## 先決條件

由業務負責人、流程擁有者、IT／資安及文件控制人員核准試點範圍、資料分類、參與者、來源工具、指標定義及停止條件。使用非敏感、獲准的流程資料；原型預設只在本機運行、沒有企業身分驗證，不得公開部署。

## 試點設定流程

1. 選定一條有明確文件版本／證據痛點、含跨部門交接、流程擁有者可投入且可觀察成效的流程。
2. 以樣本案件走查真實路徑，辨認每一階段的輸入、活動、輸出、責任人、核准點、例外和可驗證證據。
3. 指定每種文件的唯一權威來源。Microsoft 365、Google Workspace 或其他平台均可；治理索引記錄來源系統與連結，不搬移或另存文件本體。
4. 建立共享識別碼規則，關聯專案、流程、需求、文件版本、證據、核准、風險、變更及品質事件。使用現有工具建立欄位、文件索引、簽核狀態與報表視圖。
5. 先以代表性案例測試新增、連結、版本更新、退回、權限拒絕、失效連結、例外及稽核查找；由不同角色各自完成工作，記錄操作時間與阻礙。
6. 用相同定義採集基線和試點結果，業務負責人確認資料品質、是否達標及是否可複用。

## 共通索引欄位

| 欄位 | 規則 |
| --- | --- |
| 專案／流程識別碼 | 在組織範圍唯一，跨系統沿用 |
| 文件標題／識別碼／版本 | 對應來源系統中可查到的實際物件和版本 |
| 來源系統／來源連結 | 記錄權威位置；無權存取時顯示未確認 |
| 證據類型／對應需求或檢查項 | 說明此證據證明什麼 |
| 資料分類／擁有者／保存規則 | 由資料／文件治理負責人核准 |
| 提交人／時間／審查人／結果 | 保留誰何時做了什麼決定 |
| 簽核與稽核參照 | 回連來源平台核准記錄或正式決策記錄 |

## Microsoft、Google 與混合工具配置

依工具清冊逐項評估企業現有授權、API／匯出能力、群組權限、版本歷程、簽核記錄、保留政策及管理者批准。先用工具原生能力完成文件索引、表單、待辦／核准與報表；跨平台只傳遞必要識別碼、狀態、穩定連結和已核准的中繼資料。實際功能名稱與設定步驟以該租戶目前可見能力為準，不預設授權。

若 API／連接器尚未批准，使用人工登錄來源參照作為試點替代，並標示為人工同步。不得以讀取分享連結代表已驗證權限或版本；每次重要決策須由授權人直接確認來源文件和核准紀錄。

## 停止與升級條件

- 找不到權威文件版本、無法確認操作者／核准人、來源權限不符或連結不穩定：標記「無法確認」，停止該筆正式判定。
- 發現法律、安全、隱私或合約強制要求不符合：停止試點該路徑並交法遵／資安／贊助人處理，不走一般例外。
- 資料外洩、權限擴大、版本被覆寫或稽核鏈驗證失敗：暫停資料輸入，保存事件紀錄並依組織事件程序升級。
- 試點指標無有效基線、參與者不足或流程擁有者未確認規則：延後 go/no-go，不推估為達標。

## 建置決策

只有在既有工具經核准設定仍無法滿足一項或多項必要需求，且替代方案成本／風險已記錄時，才提議 MVP。決策包包含需求 ID、試點證據、目前缺口、工具擴充／人工控制方案、建置成本估計、身分與資料安全設計、營運責任及回退方案；贊助人核准後才建立平台交付基線。
