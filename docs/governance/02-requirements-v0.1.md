# 跨專案品質與文件治理領域需求基線 v0.1

**狀態：** 待業務與 IT 共同核准。通用商業情境為基線；真實部門、司法管轄區、保存年限、身分供應商及服務等級待探索工作簿確認。

**規格用途：** 本文保留領域藍圖、角色、生命週期及檢查表。原功能需求表是需求摘要；開發行為以 [05 功能與互動規格](05-functional-spec-v1.md)、[06 資料與狀態模型](06-data-and-state-model-v1.md)、[07 安全與連接器規格](07-security-integration-spec-v1.md) 為準，逐項驗收以 [04 驗收追溯矩陣](04-acceptance-test-matrix.md) 為準。業務未決事項列於 [08 決策登錄表](08-decision-register.md)。

## 角色與職責

| 角色 | 責任 | 控制邊界 |
| --- | --- | --- |
| 指導委員會／贊助人 | 重大範圍、資源、風險及例外決策 | 不代替流程負責人核對日常證據 |
| PMO／治理辦公室 | 組織政策、模板、跨專案指標及流程版本 | 不取代專案經理執行 |
| 專案經理 | 範圍、進度、成本、資源、風險與交付整合 | 不豁免不可豁免要求 |
| QA／獨立審查者 | 檢查計畫、證據充分性、缺失趨勢與放行建議 | 高風險成果須有獨立複核 |
| 文件控制人員 | 編號、版本、發布、封存與完整性 | 不得未授權修改已核准內容 |
| 工作負責人 | 依核准流程執行、留存證據、處理改善 | 不核准自己的高風險成果 |
| IT／資安／資料治理 | 身分、權限、整合、日誌、備份及資料保護 | AI 資料範圍須先核准 |
| 法遵／法規負責人 | 適用要求、司法管轄區及不可豁免控制的解釋 | 不以一般流程例外取代正式法遵判斷 |
| AI 系統負責人 | 模型／提示／版本／評估及人工覆核 | AI 不做高風險最終核准 |

同一人兼任多角時須記錄職責衝突；高風險案件安排交叉複核或升級。

## 初始 RACI（探索階段待業務核准）

`A` 最終負責一個活動；`R` 執行；`C` 諮詢；`I` 知會。這是跨專案通用基線，不取代組織正式授權或職務分工。G1–G5 的具名放行權責須在立案時指定；重大風險與例外由贊助人核准。

| --- | --- | --- | --- | --- |
| 專案立案與分類 | 贊助人 | 專案經理 | PMO、QA、工作負責人、法遵 | 文件控制、IT |
| 需求與適用要求 | 贊助人 | 專案經理、工作負責人 | PMO、QA、文件控制、IT、法遵 | AI 負責人 |
| 計畫與基準建立 | 贊助人 | 專案經理 | PMO、QA、工作負責人、IT | 文件控制、法遵 |
| 文件與系統設定 | 專案經理 | 文件控制、IT | QA、工作負責人、法遵 | 贊助人、PMO |
| 執行與過程管制 | 專案經理 | 工作負責人 | QA、文件控制、IT | 贊助人、PMO |
| 品質檢查與驗證 | QA | 獨立審查者 | 專案經理、工作負責人、文件控制、IT | 贊助人、PMO |
| 變更與影響分析 | 具授權的變更決策者 | 專案經理、變更負責人 | QA、文件控制、IT、法遵、受影響工作負責人 | PMO、贊助人 |
| 缺失、風險與 CAPA 閉環 | QA | 工作負責人 | 專案經理、文件控制、IT、法遵 | 贊助人、PMO |

| 效益追蹤與改善 | 效益擁有人／贊助人 | PMO、指定改善負責人 | 專案經理、QA、IT、工作負責人 | 文件控制、法遵 |

## 生命週期與關卡

1. 專案立案與分類：目的、價值、範圍、利害關係人、風險等級；產出章程及專案識別碼。
2. 需求與合規分析：需求來源、合約／適用要求、驗收標準及追溯矩陣。
3. 計畫與基準建立：工作分解、時程、預算、品質、資源、溝通及風險基準。
4. 文件與系統設定：分類、權限、命名、簽核、欄位及報表設定。
5. 執行與過程管制：依核准基準執行，記錄工作、決策及異常。
6. 品質檢查與驗證：依標準檢查、測試、抽樣及核對證據。
7. 變更與影響分析：評估需求、成本、時程、品質、資安、文件和下游影響；核准後執行。
8. 缺失與風險閉環：分級、根因、責任、期限、矯正、複驗與有效性驗證。
9. 階段審查與放行：檢查交付物、偏差、風險、依賴及正式決議。
10. 最終驗收與移交：驗收、操作文件、權限、訓練、保固及交接。
11. 結案與封存：完整性、版本、保存、權限、合約／財務及經驗紀錄。
12. 效益追蹤與改善：效益、缺失重發、流程成效及知識複用。

- **G1 立案：** 目的、贊助人、範圍或風險分級未確認，不啟動。
- **G2 基準：** 需求、驗收、計畫或責任未確認，不進入正式執行。
- **G3 執行：** 關鍵品質檢查未通過，受控成果不得進下一階段。
- **G4 交付：** 重大缺失、必要證據、適用要求或驗收未滿足，不放行。
- **G5 結案：** 必要文件、移交、未結責任、封存或改善計畫未完成，不結案。

一般例外須記錄原因、影響、風險接受者、補救措施、期限及核准依據。法律、安全及其他不可豁免要求不得以一般例外繞過。

## 非功能與治理需求

- NFR-01 易用性：常用導航、明確狀態、可讀錯誤及空狀態；窄螢幕仍可完成主要任務。
- NFR-02 無障礙：語義化標籤、鍵盤可操作、焦點可見、螢幕閱讀器可理解、狀態不只靠顏色呈現。
- NFR-03 權限：正式部署沿用企業身分與最小權限；存取拒絕可記錄，不能把未知權限當作允許。
- NFR-04 文件完整性：保存來源版本與引用；更新需新增版本／事件，不靜默覆寫核准狀態。
- NFR-05 隱私與 AI：依資料分類控制處理方式；AI 輸出為建議，不得自行核准、發布或豁免硬性關卡。
- NFR-06 可攜性：先記錄來源系統及連結；連接器只使用已批准的 API／權限，失敗不偽造同步成功。
- NFR-07 可維運性：發布具版本、備份／還原方式、錯誤紀錄、設定清冊、操作手冊及回退方案。

## 資料關聯與介面邊界

以 `project_id` 關聯流程執行、需求、關卡決議、文件／版本、證據、風險、變更、缺失／CAPA 與稽核事件。文件本體留在其核准權威來源；治理系統保存來源系統、穩定連結、外部版本、分類、擁有者及審查狀態。Microsoft、Google 及其他連接器須遵循同一來源參照介面；權杖、租戶 ID 和作用域由部署設定管理，不寫入流程資料或日誌。

## 假設與未決決定

通用商業情境先行；法規內容由指定產業與司法管轄區的負責人補充。正式的資料分類、保存期、身分提供者、通知管道、AI 供應者與租戶授權均待探索與安全審查核定。原型不代表這些決定已實作。
