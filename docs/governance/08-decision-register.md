# 業務決策、待確認事項與規格基線

**原則：** 規格要可建置，但不得杜撰尚未由真實組織確認的政策。此表將已固定的通用控制與需由指定責任人決定的參數分開。所有決策須有決策 ID、負責人、日期、影響需求、決議、依據及核准證據；狀態為 `OPEN` 前，相關部署／驗收條件維持 BLOCKED。

## 1. 已固定的產品原則

| 決策 ID | 已固定基線 | 適用範圍／限制 |
| --- | --- | --- |
| BASE-01 | 先用現有 Microsoft 365、Google Workspace 與混合工具進行試點，量測後才決定建置專屬平台 | 不代表所有組織已具備相關租戶授權或核准 API |
| BASE-02 | 文件權威本體保留在來源系統；治理層保存必要參照、版本關聯與決策軌跡 | 除非另經資料分類及安全核准，不匯入文件內容 |
| BASE-03 | 文件來源確認與內容／品質審查是兩項獨立控制 | 來源有效不等同內容符合；人工連結不等同 API 已確認權限 |
| BASE-04 | 通用治理基線包括 12 階段、G1–G5 關卡、品質檢查、版本追溯及例外控制 | 地方模板可增補活動；不得靜默刪除強制控制 |
| BASE-05 | AI 只協助產生流程草稿；具名流程擁有者檢查、修改並核准後才可發布 | AI 不得批准、豁免、放行或將推測當成事實 |
| BASE-06 | 正式服務端預設拒絕；核准、發布、狀態轉換有具名操作者及稽核事件 | 目前原型沒有企業身分／授權，不代表此控制已上線 |

| BASE-08 | 產業／司法管轄區專項要求只有選定後才納入需求 | 不宣稱通用產品涵蓋所有法規 |

## 3. 試點選擇與決策門

選定候選流程後以共同評分表比較：文件版本痛點嚴重性、跨部門交接數、事件／樣本可取得性、業務負責人可投入度、工具代表性、資料風險可控性與可量測改善機會。權重與門檻由贊助人核定；此文件不自行評分或預選部門。

試點結束決策：

1. **沿用現有工具：** 必要需求達標，交付治理模板、索引欄位、責任分工、操作步驟、量測結果與複用條件。
2. **調整現有工具／人工控制：** 仍有缺口但可由已核准設定／人工控制合理消除，記錄成本、風險、控制擁有人及失效偵測方式後重測。
3. **啟動平台 MVP：** 至少一項 P0 必要需求在合理現有工具方案後仍不符合；提供測試證據、缺口、替代方案成本／風險、安全方案、總擁有成本、營運責任和回退設計；由贊助人及 IT／資安核准基線。
